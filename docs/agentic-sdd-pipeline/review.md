# Autoplan review: процесс разработки

Объект review — этот пакет agentic SDD, а не архитектура финансового продукта. Премиса подтверждена пользователем: «Процесс разработки через Codex и Claude Code». Роман владеет общим планом продукта. Документация процесса подготовлена; запуск пилота и runner не выполнялись.

## Режим review

Применён `autoplan`: последовательность CEO → Design → Engineering → DX. Независимый reviewer — fresh-context subagent. Внешний Codex CLI в текущей среде недоступен, поэтому режим `subagent-only`; dual-voice и cross-model consensus не заявляются. Design пропущен: UI не создаётся, документация и будущий CLI относятся к DX. Артефакты review и test plan хранятся в этом пакете репозитория, чтобы передаваться вместе с веткой; глобальные пользовательские настройки не меняются.

## CEO: завершено

Независимое начальное review: 7/10, три замечания. P1: не хватало общего бюджета 300 минут; P2: не выбрана топология двух участников; P2: runner мог стать лишним проектом. Внесены timeline с freeze и резервом, same-host пилот с bundle-передачей для двух host, назначение пользователя Coordinator/Integrator и post-hackathon gate для runner по измеренной потребности. Повторная внешняя оценка после исправления не выполнялась.

Премисы: два человека, пять часов, coding agents, обязательный LLM продукта. Первые три ограничивают workflow, последнее передаётся Роману и не выбирает инструменты orchestrator. Наличие общего плана и headless CLI не предполагалось: вход остаётся WAITING_INPUT, интерактивный режим предусмотрен явно.

Проблема — разрыв между постановкой задачи агенту и доказанной готовностью интегрированного результата. Успех пилота — одна принятая вертикальная функция с воспроизводимым evidence; количество агентов не является метрикой. Процесс не обещает выигрыш скорости до измерения координационных расходов.

Альтернативы: один агент в общей ветке проще, но плохо отделяет ownership и независимую проверку; полноценный orchestration framework требует времени и обслуживания. Выбран небольшой протокол поверх существующих coding environments. Его обратимость сохраняется: Markdown, JSON и Git остаются понятными без runner.

Scope ограничен процессом и templates. Продуктовые требования, стек, модели и интерфейсы принадлежат общему плану Романа. Инфраструктура автоматизации вынесена за текущий хакатон и не конкурирует с обязательными функциями.

Пользовательский путь процесса: владелец передаёт план, worker получает ограниченный packet, reviewer возвращает проверяемые findings, integrator передаёт точный SHA. Узкое место — два человека должны успевать проверять и интегрировать, поэтому эти действия входят в бюджет задач. Новые функции прекращаются на отметке 210 минут.

Конкурентный риск: ручной task board может оказаться дешевле описанного протокола для двух участников. Пилот измеряет долю координации и время до принятия, а не доказывает превосходство заранее. Если отчётность тормозит работу, сокращаются второстепенные записи, но сохраняются AC, ownership и evidence.

Рост через шесть месяцев не является текущим обязательством. Возможные extensions: CI-validator и adapters после устойчивого формата, затем визуальная очередь при росте команды. Условие продолжения — повторяемая измеренная проблема, не доступность ещё одного агента.

## Реестр ошибок и восстановления

| Ошибка | Как обнаружить | Восстановление | Проверка |
|---|---|---|---|
| Нет/изменился input | Path/hash/revision | BLOCKED_INPUT, вопрос владельцу | PA-01/02 |
| Неверные refs/ownership | Task/schema/DAG review | Вернуть DRAFT, независимые задачи продолжить | PA-03/04 |
| Недоступен tool | Реальный preflight | BLOCKED_TOOL или явный interactive mode | PA-13/14 |
| Проверка упала | Exit и target SHA | Ограниченный repair либо human handoff | PA-07/09 |
| Evidence устарело | Spec/commit mismatch | STALE, повтор checks | PA-08/15 |
| Конфликт интеграции | Git и contract diff | Владельцу, без автоматического ours/theirs | PA-16 |
| Прерван coordinator | Ledger против Git | Проверить фактический side effect до resume | PA-12 |

## Реестр режимов отказа

| Отказ | Последствие | Предотвращение |
|---|---|---|
| Spec придумала новую архитектуру | Расхождение с Романом | Source refs и G1 |
| Два writer одного файла | Конфликт/потеря правок | Ownership и отдельные worktrees |
| Self-review или фраза PASS | Ложная готовность | Независимый reviewer, actual checks |
| Бесконечные repairs | Исчерпан хакатон | Deadline + attempts + общий freeze |
| SHA без objects на другом ПК | Зависимость недоступна | Bundle/разрешённый remote, verify до READY |
| Автопубликация/сырые логи | Нежелательный внешний эффект | Scoped authorization, redacted evidence |
| Runner раньше продукта | Потрачен бюджет пяти часов | Только post-hackathon backlog по метрикам |

## Решения

| ID | Фаза | Решение | Тип | Основание | Отклонённая альтернатива |
