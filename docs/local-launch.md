# Локальный запуск в Windows

Tyuin запускается из корня репозитория: Python рассчитывает аналитику, записывает результаты и через FastAPI отдаёт API и готовый React-интерфейс. Для просмотра не нужны Node, сборка frontend, GPU или аккаунт AI-провайдера.

Целевая среда — Windows x64, PowerShell и **Python 3.12**. Установка зависимостей требует доступа к PyPI; после установки основной сценарий работает локально. Живой внешний LLM не входит в проверку запуска. macOS-измерения в README остаются историческими, их время нельзя переносить на Windows.

## Подготовить окружение

Откройте PowerShell в корне checkout: здесь должны находиться `requirements.lock`, папки `moneygraph/` и `data/`. В `data/` нужны исходные `nodes.parquet`, `edges.parquet`, `transactions.parquet`, а в `moneygraph/web/` — включённая в репозиторий сборка интерфейса.

Проверьте доступные интерпретаторы и создайте новое изолированное окружение:

```powershell
py --list
py -3.12 --version
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe scripts/check_environment.py --profile runtime
```

Ожидаемые признаки успеха: версия `3.12.x`, `No broken requirements found` и строка `PASS` в preflight. При ошибке команды остановитесь и устраните её до запуска следующего шага. Preflight проверяет версии из lock-файла, импорты, исходные Parquet и локальные assets. Он не доказывает прохождение расчёта или работу интерфейса в браузере.

Если Python 3.12 уже установлен без launcher `py`, используйте полный путь к **этому** интерпретатору и оператор вызова `&`, например `& 'C:\Python312\python.exe' -m venv .venv`, заменив путь своим. Если 3.12 не установлен, установите его и повторите проверку; не подменяйте его системным 3.14. Не используйте `--system-site-packages`. Существующее окружение другой версии сохраните отдельно и создайте новое; не устанавливайте этот lock поверх чужого окружения.

Все дальнейшие команды используют `.\.venv\Scripts\python.exe` напрямую. Запуск `Activate.ps1` и изменение `ExecutionPolicy` не требуются. Не меняйте версии в `requirements.lock` ради успешной установки: сохраните текст ошибки и исправьте причину несовместимости среды.

## Запустить приложение

```powershell
.\.venv\Scripts\python.exe -m moneygraph demo --data data --out out
```

Команда заново читает три Parquet, выполняет анализ, записывает `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv`, `manifest.json`, `analysis.json` и запускает сервер. Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765) после появления адреса в терминале. `results/` содержит эталонные примеры, поэтому не указывайте его как `--out` при пересчёте.

Проверьте очередь, поиск по полному `gid`, досье и направленный граф. Контрольный пример из README: изолированный seed `100000000456947100` должен находиться поиском и иметь неизвестную роль. Три CSV доступны через «Выгрузить».

В другом терминале можно проверить API:

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/health
```

Успешный ответ содержит `status: ok` и `analysis_id`. Это проверка backend; загрузку графа и файлов интерфейса проверьте в браузере отдельно. Сервер слушает `127.0.0.1`; окно терминала должно оставаться открытым. Для остановки нажмите `Ctrl+C` в этом окне.

Если порт занят, выберите другой, например `--port 8766`, и откройте соответствующий адрес. Чужой процесс завершать не нужно. Повторный расчёт в том же `--out` перезаписывает результаты этого каталога; для отдельного прогона выбирайте новый каталог внутри `out/`.

## Пересчёт и проверка

```powershell
.\.venv\Scripts\python.exe -m moneygraph run --data data --out out
.\.venv\Scripts\python.exe -m moneygraph verify --data data --out out
.\.venv\Scripts\python.exe -m moneygraph verify --data data --out results
.\.venv\Scripts\python.exe -m pytest -q
```

`run` заканчивает работу после расчёта и проверки, без HTTP-сервера. `verify` проверяет сохранённые файлы, включая контрольные суммы. Успешные команды возвращают код `0`; наличие CSV само по себе недостаточно. PowerShell показывает код последней команды через `$LASTEXITCODE`.

Для автоматического сквозного прогона после установки используйте:

```powershell
.\.venv\Scripts\python.exe scripts/smoke_local_launch.py --data data --out out/local-launch --port 8876
```

Каталог `out/local-launch` должен отсутствовать перед проверкой: скрипт откажется перезаписывать существующий результат. Для повтора задайте новое имя, например `out/local-launch-2`, и свободный порт. Скрипт запускает собственный процесс и завершает его после проверки; он не заменяет ручную проверку графа, поиска и остановки через `Ctrl+C`.

До подтверждения всей [приёмки](specs/local-launch.md) успешный preflight или отдельный smoke не означает, что Windows V0 полностью проверен. Проверки не измеряют точность ролей: эталонной разметки нет.

## Если запуск не удался

| Симптом | Что проверить |
|---|---|
| `py -3.12` не находит интерпретатор | Установлен ли Python 3.12; при необходимости вызвать его по полному пути. Не использовать случайный `python` из PATH. |
| `VENV_REQUIRED` / `VENV_ISOLATION` | Команда должна использовать Python нового venv без `--system-site-packages`. |
| `DEPENDENCY_MISSING` / `DEPENDENCY_VERSION` / `DEPENDENCY_IMPORT` | Повторить установку `requirements.lock` тем же Python из venv, затем `pip check`. При сетевой ошибке проверить доступ к PyPI. |
| Нет исходного Parquet или `INPUT_MISSING_OR_INVALID` | Проверить `data/` и целостность checkout. CSV из `results/` не заменяют входные Parquet. |
| `FRONTEND_MISSING` или UI не загружается | Проверить комплектность `moneygraph/web/` из того же checkout. Для обычного запуска пересборка frontend не требуется. |
| Порт занят | Выбрать другой `--port`; не завершать чужой сервер. |
| `verify --out results` сообщает несовпадение hash | Не редактировать эталонные CSV/manifest. Проверить, не преобразовал ли Git LF в CRLF в старом checkout; для проверки использовать свежий checkout этой версии с `.gitattributes`. Сохранить свои изменения перед сменой checkout. |
| Русский текст в старом терминале отображается неверно | Использовать терминал с UTF-8. Файлы результатов читаются и записываются в UTF-8; не пересохранять CSV через редактор ради отображения. |
| Smoke сообщает, что output существует | Выбрать новый каталог `out/...`, сохранив предыдущий результат. |

Изменения правил ролей, исходных Parquet или эталонных hashes не являются способом исправить окружение. Папки `.venv/`, `out/`, локальные логи и секреты не входят в публикацию.

## Опциональный AI

Без `LLM_BASE_URL`, `LLM_MODEL` и `LLM_API_KEY` ассистент выдаёт локальное пояснение по рассчитанным фактам. Основная аналитика и CSV от AI не зависят. Файл `.env` автоматически не загружается; наличие такого файла само по себе не включает провайдера. Для внешнего API переменные задаются в окружении серверного процесса по [описанию в README](../README.md#ai-только-пояснения). Значения ключей не публикуются и не нужны для этой приёмки.
