# Tyuin · реализация 0.1.0 · алгоритм 1.2.0

Добавлен браузерный импорт собственных Parquet с изоляцией наборов, проверкой входа, пересчётом и CSV; сохранён AI-чат актуальной `main`. [Проверка и ограничения](custom-upload-validation.md). Пользовательская приёмка этой итерации ещё не получена.

Первая рабочая локальная версия подготовлена 23.09.2026 от документационного `main` (`0cf9e85`) в `feat/finance-workbench`. Её результаты сохранены в [исходном отчёте проверки](validation.md).

Итерация сквозного демо реализована от `main` (`0b5e0ba`) в `feat/finance-demo-scenario`. Добавлены сводка проверенного набора, глобальный поиск, top-20, карточка группы и перечень проверки. Полные объяснения приоритета и групп изменили текст результатов, поэтому версия алгоритма повышена до 1.1.0; роли, оценки, ранги и состав групп сохранены. [Проверка этой версии](demo-ux-validation.md); пользовательская локальная приёмка объединённой UX-версии `1b38d0e` получена 23.09.2026. Замеры двух репетиций с человеком ещё не зафиксированы.

Последующая UX-доработка добавляет подсветку совпадений на полной сети и единый список клиентов с фильтром перечня проверки. Аналитика, API и CSV не менялись. [Проверка этой доработки](demo-filter-validation.md).

Предыдущая компоновка сохранена в истории и [отчёте UX-итерации](ux-validation.md).

[Согласованный план](architecture.md) сохраняется как проектное основание. Фактические команды, правила и ограничения — в [README](../../README.md); доказательства — в [отчёте проверки](validation.md).

Публичное имя решения — **Tyuin**; [бренд-пакет](../brand/README.md). Внутреннее имя пакета `moneygraph`, существующие API-поля и форматы CSV сохранены; метаданные результата и объяснения групп добавлены расширением.

## Контракты

Все ответы графа и досье содержат `analysis_id`, экспорт — заголовок `X-Analysis-ID`. Идентификатор вычисляется из версии алгоритма, контрольных сумм входов и списка узлов. При изменении правил необходимо повышать версию алгоритма и пересчитывать результат.

| API | Назначение |
|---|---|
| `GET /api/health` | Готовность текущего снимка |
| `GET /api/analysis` | Сводка, узлы, рёбра с активностью по дням, сообщества и их объяснения, `dataset` со статусом проверки и временем; без подробных объяснений ролей |
| `GET /api/nodes/{gid}` | Досье, все операции узла, дневные суммы, соседи; подробное объяснение роли только в `node.role_explanation` |
| `GET /api/clusters/{cluster_id}` | Состав агрегатов и гипотеза сообщества |
| `GET /api/exports/{filename}` | Только три разрешённых CSV текущего снимка |
| `POST /api/nodes/{gid}/explain` | Сохранён для внешних API-клиентов: вопрос `role`, `priority` или `missing`; локальные факты или проверенный по контракту текст провайдера. Frontend ассистента его не вызывает |
| `POST /api/datasets` | Три Parquet в multipart (`nodes`, `edges`, `transactions`); полный расчёт и проверка; возвращает `dataset_id`, `analysis_id` |
| `DELETE /api/datasets/current` | Удаление импортированного снимка по `X-Dataset-ID` |

Все API чтения и пояснения выбирают неизменяемый снимок заголовком `X-Dataset-ID`; без него доступен набор запуска. Просроченный/неизвестный токен возвращает 410. CSV выбираются тем же заголовком, без токена в URL. Ответы API имеют `Cache-Control: no-store`. Импорт не заменяет глобальный набор и не записывает данные в репозиторий.

Временные файлы живут только во время импорта, проверенные результаты доступны в памяти одного процесса до часа; фоновая очистка просроченных снимков выполняется каждые 30 секунд. Одновременно разрешён один импорт и четыре готовых набора; новые загрузки сверх лимита отклоняются без вытеснения действующих. Ограничения тела, файлов, числа строк и распакованных колонок проверяются до анализа. Система не рассчитана на несколько worker-процессов, постоянную историю или разграничение прав по аккаунтам.

Алгоритм 1.2.0 обрабатывает календарный период входа до 366 дней; время суток нормализуется перед агрегацией, часовые пояса и числовые даты не принимаются. Проверяются числовые типы и переполнение сумм до построения графа. Правила ролей и кластеров сохранены. Исторические `results/` относятся к 1.1.0 и остаются без изменений.

Досье предыдущего узла сбрасывается при смене выбора, устаревшие запросы отменяются. Ошибки загрузки и пустые периоды показаны явно. Расчёты на клиенте не повторяются; диапазон дат влияет только на просмотр операций и активности связей.

`role_explanation` описывает фактические условия выбранного правила, невыполненные условия предыдущих правил, формулу поддержки и ограничения. Сервер исключает это поле из общей выдачи графа и из соседей досье. До загрузки досье интерфейс показывает краткое `evidence`; подробное объяснение использует только `node` с текущим `gid`.

Граф показывает окружение по всем направлениям или по входящим/исходящим цепочкам. Фильтры применяются перед обходом: путь не может пройти через скрытого участника. В направленном режиме остаются только пройденные рёбра; при всех направлениях — все связи между включёнными узлами. Выбранное ребро связано с фильтром операций и сохраняет выделение после перехода к его участнику. При входящем обходе переход с дальнего ребра выбирает получателя, чтобы сохранить выбранную связь в новом окружении.

## Сквозной UX

Паспорт набора использует реальные данные manifest. CLI добавляет `verification.status=passed` только после успешной проверки CSV. Без этого статуса API/UI сообщают, что проверка не подтверждена. `full_run_seconds` означает обработку, запись и проверку, а не время установки или полного запуска процесса с импортами.

По умолчанию показаны вся сеть и все клиенты. Во вкладке «Клиенты» расположены «Все клиенты», «На проверку N», «Топ-20» — последний совпадает с обязательным CSV. Общие фильтры сужают обычный список и перечень; изменение общего фильтра из top-20 переключает список на всех клиентов. В каждой строке есть действие добавления/удаления из перечня; выбор строки сохраняет режим графа. Полный gid ищется глобально, выходит из ограничений review/top, сбрасывает мешающие фильтры и открывает роль и окружение. При подсветке сохраняется вся сеть. Фильтры списка всегда доступны, их переключение очищает поиск. Досье имеет вкладки приоритета, роли, операций и дополнительного ассистента.

При включении «Подсвечивать на всей сети» Graph получает отдельно полный набор и множество совпадений: классы/оформление изменяются без пересоздания топологии или fit при смене фильтров. В противном случае множество совпадений ограничивает обход. Совпавшие узлы имеют ореол, выбранный клиент — отдельный тёмный контур; показываются размер сети и число совпадений. Пустая выборка не превращается в полную по умолчанию.

Выбор сообщества открывает карточку группы и её граф, оставляя все 88 групп доступными слева. Карточка содержит состав, внутренний оборот, наблюдаемые межгрупповые потоки, функцию/неопределённость, основания и пороги. Возврат восстанавливает исходного клиента, запрос, вид списка, фильтры и режим подсветки. Правила гипотез документированы в README и manifest; они не меняют Louvain, роли или ранжирование.

Перечень проверки хранит выбранные gid в состоянии интерфейса с текущим `analysis_id`; это пользовательский выбор, не дополнительная оценка алгоритма. В режиме «На проверку» общая строка клиента дополнена полным gid, основанием и следующим действием. Копируется весь перечень, включая клиентов, скрытых текущими фильтрами; это подписано рядом с кнопками. При недоступном clipboard появляется текстовое поле для ручного копирования. Перезагрузка очищает перечень; постоянное хранение пока не реализовано.

На широком экране панели занимают оставшуюся высоту окна и прокручиваются независимо. На узком экране идут вертикально. Справка использует нативный `dialog`, закрывается по Escape и возвращает фокус. Формулы приоритета в CSV, API, досье и локальном объяснении согласованы.

Назначенная роль подписана как гипотеза; `unknown` означает недостаток данных. Поддержка признаками отображается отдельно от приоритета в баллах из 100. Проценты точности не заявляются: размеченной проверки нет.

## Ассистент с ключом в браузере

Текущая итерация добавляет свободный чат с OpenAI по уже рассчитанным фактам выбранного клиента. При открытии «Ассистента» без ключа появляется окно ввода, которое можно закрыть для работы с локальными объяснениями. Перед вводом объяснено, что ключ остаётся только в памяти frontend, не отправляется на сервер Tyuin и теряется после перезагрузки. При запросе он передаётся непосредственно OpenAI для авторизации. Приложение не сохраняет ключ или диалог в браузерные хранилища, URL или файлы.

Состояние «Ключ задан» и действие удаления видны пользователю. Ввод ключа не проверяет доступ к API: проверка происходит при первом вопросе. Удаление очищает ключ и чат, отменяет текущий запрос и исключает поздний ответ. При смене выбранного клиента или уходе со вкладки запрос отменяется и история очищается; ключ остаётся до удаления, перезагрузки или смены набора. Смена набора пересоздаёт рабочую область, очищает чат и ключ; факты ассистента проверяются по gid и analysis_id текущего досье.

Запрос направляется на фиксированный `https://api.openai.com/v1/responses` с `gpt-4.1-mini` и `store: false`. Автоматический контекст содержит ограниченные агрегаты и объяснения текущего клиента без исходных gid, операций и полного графа. Пользовательский вопрос и история текущего диалога передаются как текст; вручную введённые сведения входят в запрос. Сохранение у провайдера определяется [правилами OpenAI](https://developers.openai.com/api/docs/guides/your-data); `store: false` не является обещанием полного отсутствия журналов.

Три локальных объяснения собираются frontend из загруженных фактов и не вызывают backend LLM. Старый серверный endpoint пояснений с `LLM_*` сохранён для внешних клиентов API, но не служит источником ключа или резервным маршрутом нового чата. Ответ OpenAI отображается как пояснение и не изменяет результаты анализа или действия пользователя.

Живой OpenAI API для нового чата пока не проверен. Контракт и жизненный цикл ключа проверены автоматическими тестами и в браузере с имитацией ответов ([отчёт](openai-assistant-validation.md)); доступ конкретного аккаунта, квоты и качество реального ответа такой проверкой не подтверждаются. [Спецификация, критерии и статус](../specs/openai-browser-assistant.md).

## Что вошло в первую рабочую версию

Реализован сквозной V0 и раскрытие доказательств из первой итерации: дневная активность, операции и FIFO. Поэтому первый опубликованный алгоритм сразу использует временное соответствие в поддержке transit; промежуточная формула «только сходство сумм» отдельно не выпускалась.

Визуальная итерация включает три связанные панели, типографику, формы seed/границы, компактные подписи и адаптивную компоновку. Пользовательская оценка выразительности интерфейса остаётся частью локальной приёмки.

В первой рабочей версии реализован серверный адаптер внешнего AI, но живой API не проверен. Для этого адаптера проверены локальные объяснения, валидный имитированный ответ, неверные ссылки/JSON и тайм-аут. Свободный чат добавлен отдельной текущей итерацией, описанной выше; исторические проверки адаптера не считаются проверкой нового браузерного чата.

Масштабирование и дополнительные детекторы из ТЗ описаны как развитие; они не включены в измеренный результат этой версии.
