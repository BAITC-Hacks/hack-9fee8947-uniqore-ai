# Tyuin · пять минут живого демо

Сценарий соответствует реализованному интерфейсу алгоритма 1.1.0. [Отчёт проверки](demo-ux-validation.md), [спецификация](../specs/finance-demo-rehearsal.md). Браузерные переходы проверены; выступление команды по секундомеру и объяснение трёх заданных проверяющим gid за минуту ещё требуют репетиции.

## Подготовка

Установить зависимости по [README](../../README.md). Открыть окно браузера не уже 1280 px. Подготовить одну схему из раздела README «Как получается результат». Расчёт исходных Parquet запускается живьём, установка окружения в пять минут не входит:

```bash
python -m moneygraph demo --data data --out out
```

Открыть адрес, напечатанный командой. Если основной порт занят, добавить `--port 8766`. На Windows использовать Python виртуального окружения, как указано в README.

## Основной показ

| Время | Действие в текущем интерфейсе | Что объяснить |
|---|---|---|
| 0:00–0:35 | Запустить `demo`; во время расчёта показать схему, затем открыть интерфейс | Исходные данные → метрики → роли и группы → обоснованный порядок проверки. Три CSV проверяются до старта сервера |
| 0:35–1:00 | Показать сводку набора и «Обзор сети» | 81 исходный клиент, 2 248 узлов, 3 119 связей, 4 840 операций; стрелки — направления, цвет — роли или сообщества |
| 1:00–1:50 | «Клиенты» → «Топ-20 всего набора» → первый клиент `100000003684369100`. «Приоритет», затем «Роль»; «Добавить на проверку» | Четыре фактора ранга; роль и её поддержка — отдельная оценка. Вход seed неполон |
| 1:50–2:35 | Найти `100000000031787100`, Enter. Показать «Роль», вход/выход, одну связь и её операции | Вход и выход по 90 000 KZT, поддержка транзитной гипотезы 78/100, приоритет 58/100. Временная совместимость не доказывает передачу тех же денег |
| 2:35–3:20 | Открыть сообщество клиента. Показать состав, внутренний и межгрупповые потоки, гипотезу, основания и ограничения. Вернуться к клиенту | Гипотеза следует из направления потоков и явных порогов, а не только из размера группы или доминирующей роли |
| 3:20–4:00 | Найти `100000000018102100`. Показать неизвестную роль, границу четвёртого колена и следующий шаг. При необходимости добавить в перечень | Отсутствие видимого выхода на границе не доказывает, что это конечный получатель |
| 4:00–4:40 | «На проверку» → проверить выбранные gid/основания/следующие действия → «Скопировать перечень». «Выгрузить» → три CSV | Перечень — выбор аналитика; обязательный top-20 — глобальный рейтинг. Все три CSV относятся к целому набору за месяц |
| 4:40–5:00 | Итог и ограничения, резерв на переходы | Получены проверяемые кандидаты для дальнейшей работы; роль, группа и приоритет не означают виновность |

Основной показ включает три клиента и одну группу. AI-пояснение, подробное исследование дат, изолят и повторный `verify` — резервные действия. Команда `demo` уже выполняет встроенную проверку файлов. Время её таймера — обработка, запись и проверка CSV; оно не включает импорты до старта таймера, установку и браузер. Полный процесс отдельно измерен в [benchmark](../../results/demo-scenario-benchmark.json).

Список проверки сохраняется при переходах в открытом анализе. Перед перезагрузкой скопируйте его: постоянное сохранение не реализовано. Три обязательных CSV не меняются от этого списка или экранных фильтров.

## Отдельная минутная проверка произвольных gid

Проверяющий выбирает три gid из полного набора без подбора командой. На каждый — ориентир 20 секунд:

1. Ввести полный gid и нажать Enter. Поиск работает независимо от фильтров и сразу открывает «Роль» и окружение.
2. Назвать гипотезу либо причину неопределённости.
3. Показать наблюдаемые значения и пороги. Для остаточной роли «Периферия» раскрыть «Как выбрана роль и рассчитана поддержка»: там видны причины невыполнения предыдущих правил.
4. Назвать существенное ограничение наблюдения.

Зафиксировать фактическое время всего упражнения и затруднения. Автоматическая проверка трёх случайных gid из отчёта не является измерением речи команды и не заменяет эту приёмку.

Дополнительно проверить `100000000456947100`: изолированный seed находится и показывается одним узлом без связей. Для незнакомого gid интерфейс сообщает, что его нет в наборе. Даты фильтруют операции, а роли, приоритеты и CSV остаются месячными.
