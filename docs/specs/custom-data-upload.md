# Загрузка собственных данных

Статус: реализовано, проверено и принято пользователем 23.09.2026 на версии `2269362`; слияние разрешено. [Отчёт](../finance/custom-upload-validation.md), [PR #23](https://github.com/BAITC-Hacks/hack-9fee8947-uniqore-ai/pull/23).

Как AML-аналитик, я хочу загружать собственные данные об участниках, связях и транзакциях в формате исходного набора, чтобы строить граф и проводить анализ на своих данных.

## Основание и границы

Загрузка исходной выгрузки входит в сценарий оригинального ТЗ, раздел 3, шаг 2. Отдельный браузерный импорт собственных наборов — согласованное расширение продукта. Сохраняется обязательный запуск из исходных Parquet одной командой и три CSV фиксированной схемы. Оригиналы кейса не изменяются.

Первая версия принимает обезличенную выборку с той же семантикой, что у кейса: исходящие связи до четвёртого колена, seed с глубиной 0, переводы в KZT от 5 000. Произвольные таблицы, сопоставление колонок, Excel/CSV, обогащение и хранение истории не входят в эту задачу.

## Контракт входа

| Файл | Обязательные поля |
|---|---|
| `nodes.parquet` | `gid` int64, `depth` целое 0–4, `is_seed` bool |
| `edges.parquet` | `src`, `dst` int64; `sum_kzt` число; `n_tx` положительное целое; `depth` целое 1–4 |
| `transactions.parquet` | `src`, `dst` int64; `date` календарная дата без часового пояса; `sum_kzt` число |

Нужны все три файла, непустой набор клиентов и хотя бы одна операция. Каждый gid уникален в nodes; концы связей и операций существуют в nodes. Пары edges уникальны; их суммы в тиынах и количества точно соответствуют transactions. Дубликаты реальных операций сохраняются. `is_seed` соответствует `depth=0`; денежные значения положительны, конечны, с точностью до тиына.

Период определяется по минимальной и максимальной дате операций, до 366 календарных дней включительно. Дата нормализуется к календарному дню перед агрегацией. Привязки к июлю 2026 нет; текущие правила ролей, границы четвёртого колена и приоритетов сохраняются. Число узлов может быть меньше 20: top содержит `min(20, N)` строк.

Продуктовые ограничения браузерного импорта: 10 MiB на файл; 5 000 узлов, 20 000 связей, 100 000 операций. Дополнительно ограничены размер HTTP-тела, распакованных данных и число одновременных расчётов. Эти лимиты не являются условиями организатора и не заявляют производительность для больших графов.

## Пользовательский сценарий

1. Нажать «Загрузить данные», увидеть формат и ограничения, выбрать три файла.
2. Запустить загрузку; видеть состояние обработки. Текущий результат остаётся доступен при отказе.
3. Сервер проверяет вход, рассчитывает аналитику, записывает и проверяет CSV.
4. Только успешный набор открывается в интерфейсе: паспорт, граф, досье, группы, операции и выгрузки относятся к одному анализу.
5. Старые фильтры, выделение, перечень проверки, пояснения, AI-чат и ключ AI сбрасываются при переключении.
6. Можно вернуться к набору, с которым запущено приложение. Перезагрузка вкладки сохраняет ссылку на импорт до истечения срока; после перезапуска сервера или истечения срока показано понятное восстановление.

Файлы передаются серверу, на котором работает Tyuin. При локальном запуске это компьютер пользователя; при размещении на сервере — соответствующий сервер. Исходные загруженные файлы удаляются после обработки, результат доступен до часа; фоновая очистка памяти выполняется каждые 30 секунд. Не более четырёх импортированных наборов одновременно; заполненное хранилище не вытесняет чужой действующий набор. Токен набора хранится в sessionStorage вкладки и не включается в URL. Это временное разделение результатов, не система аккаунтов и прав доступа.

## API и согласованность

- `POST /api/datasets`: multipart с полями `nodes`, `edges`, `transactions`; ответ `dataset_id`, `analysis_id`.
- Заголовок `X-Dataset-ID` выбирает временный снимок для всех API чтения, пояснений и CSV. Без него используется исходный снимок запуска.
- Неизвестный/истёкший токен возвращает 410, без скрытой подстановки другого набора.
- `DELETE /api/datasets/current` с заголовком удаляет только соответствующий импорт.
- API запрещает кеширование. CSV скачиваются запросом с заголовком и содержат правильный `X-Analysis-ID`.

## Проверка предложения

Первоначальная база: `6620aa1`; перед итоговой проверкой ветка перенесена на `7b1cddf` (`main`) с сохранением браузерного AI-чата. По протоколу разработки предложение принято к реализации с проверками изоляции, ограничений загрузки/распаковки, календарных дат, атомарного переключения и малых наборов. Решение расширяет применимость и воспроизводимость; баллы жюри, превосходство или точность не заявляются. Обязательный сценарий должен работать без аккаунта и внешнего AI.

## Критерии приёмки

- Собственный небольшой набор с большими int64 gid, изолированным клиентом и периодом через границу года проходит полный путь до CSV и видимого графа.
- Ошибки схемы, согласованности, неполный комплект, повреждённый файл, превышение объёма/лимитов понятны и сохраняют активный результат.
- Два токена возвращают свои результаты; набор запуска неизменен. Все API и CSV согласованы.
- Повторная загрузка, перезагрузка вкладки, возврат к исходному набору и истечение срока не смешивают данные или пользовательское состояние.
- Дневные фильтры корректны для одного дня, перехода месяца/года и високосного февраля; период больше 366 дней отклоняется.
- Исходный кейс сохраняет 2 248 узлов, 3 119 связей, 4 840 операций, 19 изолированных seed, 444 граничных узла и 20 строк top. Все три CSV проходят штатную проверку; запуск менее 300 секунд.
- Интерфейс проверен в браузере на широком и узком экранах, включая доступность формы с клавиатуры и ошибки.
- README, фактическая архитектура и отчёт проверки обновлены. Слияние — только после пользовательской приёмки зафиксированного коммита.
