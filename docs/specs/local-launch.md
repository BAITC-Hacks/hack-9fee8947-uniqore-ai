# Локальный запуск Tyuin в Windows

Статус: **в реализации и локальной проверке**. Источник текущей реализации — `main`, baseline `18c412d4d90daa161456bc7ebacc23e4874cd26e`. Документ задаёт условия приёмки; не является отчётом об успешном запуске.

Как участник команды или проверяющий, я хочу запустить Tyuin на Windows по README, чтобы получить расчёт, три CSV и интерфейс без ручной сборки frontend и обязательного AI-аккаунта.

## Решение

Использовать существующий Python 3.12 → FastAPI → React-пайплайн. Сначала подготовить изолированное окружение и показать работающие API/UI, затем проверить полный существующий V0. Изменять только подтверждённые проблемы локального запуска: диагностику, UTF-8, одинаковые CSV bytes между платформами и правила checkout. Аналитические правила, исходные данные и эталонные результаты сохраняются.

Архитектура запуска: `data/*.parquet → moneygraph demo → расчёт + CSV/manifest → FastAPI 127.0.0.1 → moneygraph/web`. Node нужен разработке frontend, но не установленному runtime. Установка Python-зависимостей может требовать PyPI; основной сценарий после неё работает без внешнего AI.

Подробная декомпозиция и контракты — в [зафиксированной SDD-спецификации v2](https://github.com/BAITC-Hacks/hack-9fee8947-uniqore-ai/blob/0f74000f920cdbcad886ba91a69b0c9eac9076eb/docs/sdd/local-launch/spec.md); состояние выполнения и результаты ведутся в [ветке codex/local-launch](https://github.com/BAITC-Hacks/hack-9fee8947-uniqore-ai/tree/codex/local-launch/docs/sdd/local-launch). Новая база `18c412d` сохраняет согласованный объём, а приведённый ниже контракт учитывает актуальные правила проекта.

## Задачи

1. **T-001:** Python 3.12 venv, `pip check` и preflight; прежние версии lock сохранены, добавлен pin Windows-зависимости colorama.
2. **T-002:** проверить Windows CLI/API/UI; исправить воспроизведённые проблемы переносимости и добавить необходимую smoke-проверку.
3. **T-003:** параллельно T-002 подготовить PowerShell-инструкцию, ошибки и условия приёмки.
4. **T-004:** собрать общий candidate commit, выполнить чистую установку, автоматические и браузерные проверки, независимое review.

## Приёмка

Команды выполняются из корня репозитория; в Windows `python` ниже означает `.\.venv\Scripts\python.exe`. Полная инструкция — [docs/local-launch.md](../local-launch.md).

| AC | Проверяемый результат | Команда или сценарий |
|---|---|---|
| AC-001 | Изолированный Python 3.12 venv и версии из lock | Установка `requirements.lock`, `python -m pip check`, `python scripts/check_environment.py --profile runtime` |
| AC-002 | Чистый checkout запускается с готовыми assets без Node | Новое окружение, preflight, smoke; без frontend build |
| AC-003 | `demo` пересчитывает данные, API/UI доступны на loopback; единый `analysis_id` | `python -m moneygraph demo --data data --out out`; `/api/health`, API, manifest и CSV; `Ctrl+C` освобождает порт |
| AC-004 | Реальный граф, очередь, поиск, досье, три выгрузки и объяснение | Браузером пройти основной сценарий README, включая изолят и границу наблюдения |
| AC-005 | Основной сценарий без Node, LLM-ключей и внешних ресурсов интерфейса | Среда без Node и трёх LLM-переменных; просмотр сетевых запросов браузера; локальный ответ ассистента |
| AC-006 | Проблемы данных/assets/порта дают диагностируемую ошибку | Негативные тесты на изолированных fixtures; чужие процессы и файлы не затрагиваются |
| AC-007 | Windows run/verify/tests проходят; полный run занимает <300 с | `python -m pytest -q`; `verify` свежего output и `results`; измерение нового процесса с импортами, записью и проверкой |
| AC-008 | Нет новых секретов; исходные Parquet и аналитические правила сохранены | Просмотр diff; `.env`, venv и локальный output не публикуются; canonical hashes не меняются ради тестов |
| AC-009 | PowerShell-инструкция воспроизводима вторым участником | Прямой вызов Python venv, без активации и смены ExecutionPolicy; фактический проход README |
| AC-010 | Независимое review и evidence относятся к одному candidate SHA | Записать версии среды, SHA, команды, результаты, ограничения и исполнителей; повторить затронутые проверки после исправлений |

Автоматический сквозной сценарий: `python scripts/smoke_local_launch.py --data data --out out/local-launch --port 8876`. Output должен быть новым. Успешный preflight подтверждает подготовку среды, успешный smoke — только покрытые им сценарии. Статус полного Windows V0 требует всех AC, включая браузер, независимую проверку и проход инструкции вторым участником. Пропущенные проверки не считаются пройденными.

## Границы и выпуск

Не входят: cloud/Docker, wheel-поставка, новая архитектура, пересборка UI, новые правила аналитики и проверка живого внешнего LLM. Исторические macOS-измерения сохраняются отдельно; Windows-время фиксируется с условиями измерения, без включения установки и без заявления о сбросе OS cache, если его не было.

Рабочая ветка → локальная проверка → PR в `main`. Слияние требует подтверждения локальной приёмки конкретной версии по [правилам разработки](../development-workflow.md). До приёмки задача остаётся в [бэклоге](../backlog.md), а не в `done`.
