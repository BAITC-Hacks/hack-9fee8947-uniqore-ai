# Объяснить назначение кластеров через структуру потоков

Статус: запланировано; реализация и приёмка не выполнены. [Бэклог](../backlog.md).

## Задача
Как AML-аналитик, я хочу понимать возможное назначение выделенной группы и основания этой гипотезы, чтобы решать, что проверять дальше.

Приоритет: высокий, перед конкурсной сдачей. Риск по обязательному пункту 4 кейса: в `clusters.csv` требуется гипотеза о назначении кластера.

## Найденная проблема
Поле `hypothesis` сейчас повторяет размер, число seed, преобладающую роль и внутренний оборот. Оно не объясняет возможную функцию группы. Например, сообщество 48: 26 узлов, 14 seed, преобладает периферия — этого недостаточно для содержательной гипотезы.

## Что сделать
- Вывести объяснимые правила групповых гипотез из наблюдаемой структуры и направлений потоков: возможный сбор средств, распределение, транзит или смешанная структура.
- Указывать конкретные рассчитанные основания и ключевые узлы, а также ограничения наблюдения.
- Если признаки недостаточны, явно писать, что назначение определить нельзя, с причиной.
- Использовать одинаковые гипотезы в CSV, API и интерфейсе; документировать правила.

## Критерии готовности
- [ ] У каждого кластера есть содержательная гипотеза либо обоснованная неопределённость; текст не ограничивается пересказом размера и оборота.
- [ ] Вывод воспроизводимо следует из метрик и правил, без списков «правильных» gid, внешнего обогащения и вымышленных атрибутов.
- [ ] Учтены изоляты, граница четвёртого колена и неполные потоки; сообщества не объявляются преступными группами.
- [ ] Проверены обычное сообщество, сообщество с несколькими seed, пограничный случай и изолят; численные основания согласованы с исходными данными.
- [ ] CSV/API/интерфейс показывают согласованный результат; сохранены схемы выгрузок и покрытие всех 2 248 узлов.
- [ ] README и отчёт проверки обновлены; выполнены затронутые тесты и сквозной пересчёт менее 300 секунд.
