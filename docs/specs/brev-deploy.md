# Конфигурация деплоя Tyuin на NVIDIA Brev

## Задача и границы

Как участник команды, я хочу развернуть Tyuin на NVIDIA Brev из конфигурации репозитория, чтобы показывать работающий интерфейс без ручной настройки Python.

Ветка: `codex/brev-deploy`, итоговая база: `18c412d` (`origin/main`). Объём: контейнеризация существующего приложения и инструкция; создание облачной VM, публикация образа и запуск платных ресурсов в эту задачу не входят.

## Решение

- Python 3.12, зависимости из `requirements.lock`, готовый frontend из `moneygraph/web/` и три исходных Parquet входят в образ.
- Один процесс `python -m moneygraph demo` пересчитывает данные, проверяет CSV и запускает API с интерфейсом на порту 8765. GPU и внешний LLM не обязательны.
- Контейнер работает без root, проверяется через `/api/health`, результаты сохраняются в Docker volume. При перезапуске выполняется новый расчёт.
- Корневой Compose собирает образ из checkout; отдельный Compose для Brev запускает заранее опубликованный образ без локального build context.
- Секреты задаются окружением. Контекст сборки ограничен явным списком файлов. Туннель Brev или SSH задаёт доступ к приложению, в котором нет собственной авторизации.

## Приёмка

1. Оба Compose-файла проходят `docker compose config --quiet`; Brev-конфиг требует `TYUIN_IMAGE`.
2. Образ собирается, контейнер переходит в `healthy`, отдаёт интерфейс и API.
3. `verify` подтверждает 2 248 ролей, 88 кластеров и 20 приоритетных узлов; три CSV доступны через API одного снимка.
4. Существующие тесты проходят в контейнере; после перезапуска основной сценарий работает.
5. Инструкция различает локальную проверку, публикацию образа и непроверенный облачный запуск. Локальный запуск без Brev сохраняется.

Инструкция и результаты проверки: [деплой на Brev](../deployment/brev.md). До локальной приёмки задача остаётся в разделе «В работе».
